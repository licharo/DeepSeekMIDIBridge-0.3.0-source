## 1. 它是什么

一句话：**一个 VST3 插件，能读到你其它音轨正在弹的 MIDI，把它当作参考素材发给 DeepSeek，按你的自然语言要求写出新的 MIDI，存成标准 `.mid` 文件供你拖进 Live。**

它由三个能力组成，可以同时开：

| 角色 | 做什么 | 用在哪种接法 |
|---|---|---|
| **捕获端** | 把本轨收到的 MIDI 变成音符快照，写进本机“共享总线”，让同一工程里其它实例看得见 | 方式 A（多个实例协作） |
| **生成端** | 把勾选的参考素材 + 你写的文字要求发给 DeepSeek，解析返回的 JSON，写成 `.mid` 文件 | 全部接法 |
| **播放端**（可选） | 让生成的音符实时从插件输出（跟随宿主走带 / 循环 / 自己跑时钟“试听”） | 可选，取决于宿主 |

工作流程：

```
源音轨（贝斯/鼓/和声…）                     目标音轨
┌───────────────────────┐                  ┌──────────────────────────────┐
│ DeepSeek MIDI Bridge  │  共享总线(文件)   │ DeepSeek MIDI Bridge         │
│ 角色：捕获/发送        │ ───────────────▶ │ 角色：生成                    │
│ 捕获本轨 MIDI 并发布   │                  │ 勾选参考轨 → 写要求 → 调 API  │
└───────────────────────┘                  │ → 写 <工程文件夹>\*.mid       │
                                           │ → 自动打开文件夹，拖进 Live   │
                                           └──────────────────────────────┘
```

> 也可以完全不用共享总线：把目标轨的 **MIDI From** 指向源轨（方式 B），插件直接就能看到对方。
> 或者把任意 `.mid` 文件**拖进插件窗口**当参考（方式 B+）。

## 2. 安装与卸载

### 2.1 用安装包一键安装

双击 **`DeepSeekMIDIBridge-Setup-0.3.0.exe`**，出现安装窗口：

| 界面元素 | 说明 |
|---|---|
| **安装 DeepSeek MIDI Bridge**（标题） | 当前是安装模式。副标题显示版本号与“不需要额外的运行库”。 |
| **插件安装位置**（输入框） | 插件 `.vst3` 装到哪里。默认 `C:\Program Files\Common Files\VST3`（**Ableton Live 只会自动扫描这一个系统目录**，所以默认就是它）。如果之前装过，会记住上次的位置。 |
| **浏览…** | 打开文件夹选择框，换成别的目录（例如 D 盘的 VST3 目录）。换了以后要在 Live 里手动把这个目录加进 `Plug-Ins → VST3 Plug-In Custom Folder`。 |
| **同时安装纯 MIDI 版本（Cubase / Bitwig 等宿主的 MIDI 插槽用；Ableton Live 无法加载它）**（复选框） | 勾上时会额外装上没有音频总线的 `DeepSeek MIDI Bridge (MIDI).vst3` —— Cubase/Nuendo 的 MIDI 插槽、Bitwig 的 Note FX 只能用这个版本。**Ableton Live 拒绝加载它**（日志里是 `no valid audio input bus`），所以默认**不勾选**；不勾选时安装程序还会顺手删掉以前留下的那个目录。 |
| **开始安装**（蓝色主按钮） | 开始复制文件。过程中进度条 + 状态文字会显示每一步（检查宿主 → 读取安装内容 → 安装文件 → 安装卸载程序 → 记录安装清单 → 登记到“应用和功能” → 完成）。 |
| **退出** | 关掉安装程序。安装中会变成“请稍候…”。 |
| **完成**（安装成功后按钮变化） | 关闭窗口。同时左下角会显示下一步提示和卸载程序路径。 |
| **打开插件文件夹**（安装成功后按钮变化） | 用资源管理器打开刚刚的插件目录，方便确认。 |

安装程序会做的事：

1. 把 `.vst3` 目录树（含 `Contents\x86_64-win\*.vst3` 与 `Contents\Resources\moduleinfo.json`）复制到所选目录；
2. 在**程序目录**（一般为 `C:\Program Files\DeepSeek MIDI Bridge`，没权限时自动退到
   `%LOCALAPPDATA%\Programs\DeepSeek MIDI Bridge`）放四样东西：
   `卸载 DeepSeek MIDI Bridge.exe`、`install-manifest.txt`（安装清单）、`安装说明.txt`（速览）、`使用手册.docx`（本手册）；
3. 在注册表登记一条卸载项，于是 Windows“设置 → 应用 → 已安装的应用”里会出现
   **DeepSeek MIDI Bridge (VST3 插件)**；
4. 如果检测到 Ableton Live 正在运行，会**拒绝安装并提示先关闭**（插件文件被占用，装不进去）。

> **权限**：写入 `Program Files` 需要管理员权限。安装程序只在确实写不进去时才弹 UAC 请求提权；
> 如果你拒绝提权，它会提示你改用用户目录（例如 `%LOCALAPPDATA%\Programs\Common\VST3`）。
> **没有代码签名证书**，所以第一次运行 Windows 可能提示“已保护你的电脑”：点 **更多信息 → 仍要运行**。

### 2.2 卸载

两个入口，效果一样：

* “设置 → 应用 → 已安装的应用”里的 **DeepSeek MIDI Bridge (VST3 插件)** → 卸载；
* 或者双击程序目录里的 **`卸载 DeepSeek MIDI Bridge.exe`**。

卸载窗口里每一项：

| 界面元素 | 说明 |
|---|---|
| **卸载 DeepSeek MIDI Bridge**（标题） | 当前是卸载模式。副标题：“只删除本插件自己的文件；其它插件和你的音乐文件都不会动”。 |
| 摘要文字 | 显示将要从哪些目录删除（插件目录、程序目录），以及“安装清单记录了 N 个文件，只会删这些”。如果**没有安装清单**（例如插件是手动复制进去的），会列出按“文件夹名 + moduleinfo 内容”确认过的目录。 |
| **同时删除本机设置 / 素材库 / 共享总线**（复选框，默认**勾选**） | 删除 `%LOCALAPPDATA%\DeepSeekMidiBridge`（API Key、素材库、总线、诊断日志）。不想丢配置就取消勾选。 |
| **同时删除我生成的 MIDI 与工程文件夹**（复选框，默认**不勾选**，橙色警示） | 删除 `文档\DeepSeek MIDI Bridge`（你生成的 `.mid` 和每个工程的素材）。**默认保留**，只有你手动勾选才会删。 |
| **开始卸载**（红色按钮） | 开始卸载。如果 Live 正在运行会先提示关闭。 |
| **取消** | 关掉窗口，什么都不做。 |
| 结果摘要 | 卸载完成后列出“已清理的目录”和“保留（没动）”的路径与数量。 |

**卸载的安全保证（这是设计目标，不是宣传语）：**

* 只删除**安装清单里记录的文件**，并且每个路径都必须落在
  `<插件目录>\DeepSeek MIDI Bridge.vst3`（或 `(MIDI)` 版）或程序目录之内 —— 即使清单被改过，
  也够不到别的插件；
* 目录只会在**变空之后**才被删掉；如果发现有不是本插件的文件留在里面，会**保留整个目录**并在结果里写明“保留了 N 个不属于本插件的文件”；
* 无清单的老安装只按“文件夹名 + `moduleinfo.json` 内容”双重确认后才删；
* 卸载程序最后会删掉自己（先复制到 `%TEMP%`，由副本删除本体），并在重启时清理那个临时副本。

### 2.3 用脚本安装（开发用）

```powershell
cd <项目目录>
pwsh -File scripts/build.ps1                 # 构建全部（含安装程序）
pwsh -File scripts/install_vst3.ps1          # 直接把构建产物复制到 VST3 目录（不写注册表）
pwsh -File scripts/build_installer.ps1       # 打包出 dist\DeepSeekMIDIBridge-Setup-<版本>.exe
pwsh -File scripts/test_installer.ps1        # 安装/卸载的端到端自检（21 项断言）
```

`install_vst3.ps1` 会同时装到 `%LOCALAPPDATA%\Programs\Common\VST3` 和
`C:\Program Files\Common Files\VST3`（能写的话），并在最后自动删掉 `(MIDI)` 版本。

### 2.4 在 Ableton Live 里启用

1. 打开 Live → **设置（Settings）→ Plug-Ins**；
2. 勾选 **Use VST3 Plug-In System Folders**（如果你把插件装到了自定义目录，再勾
   **Use VST3 Plug-In Custom Folder** 并指向那个目录）；
3. 点 **Rescan**（按住 **Alt** 点 Rescan = 完整重扫描，换了新版本后建议这样）；
4. 浏览器左侧出现 **Plug-Ins → VST3 → DeepSeek MIDI Bridge**，拖到任意 MIDI 轨的设备链上即可。

## 4. ① 其它音轨的 MIDI（素材区）

这一栏列出**当前工程**里所有能当作参考的 MIDI，以及管理它们的按钮。

### 4.1 素材列表

每一行的格式是：

```
✔  贝斯  128 个音符, 4 小节, 128.0 BPM
│  └── 名称（可改）  └── 音符数、小节数、宿主 BPM
└── ✔ = 会作为参考发给模型；○ = 不参与（灰色）
```

| 操作 | 效果 |
|---|---|
| **左键单击一行** | 切换 ✔/○：是否把这一段作为参考素材发给模型。同时右侧钢琴卷帘会预览这一段。 |
| **右键单击一行** | 弹出菜单（见下）。 |
| 列表为空 | 显示“（没有数据）”：说明插件还没看到任何 MIDI —— 见 §8 的四种接法。 |

右键菜单：

| 菜单项 | 作用 |
|---|---|
| **用作参考 / 取消参考** | 等同于左键单击，切换 ✔/○。 |
| **重命名...** | 在行内出现输入框，改这一段的显示名（回车确认，Esc 取消，点别处也确认）。 |
| **删除这一段** | 只删这一条：保留段删掉本机留档，库里的条目删磁盘上的那条，导入的素材只从列表移除。 |
| **清空本机捕获（含保留段）** | 清掉本实例当前捕获 + 所有自动保留段 + 库里来源是“捕获”的条目。 |

行里的来源说明：捕获来的写“捕获 HH:MM:SS”，导入来的写“导入: 文件名.mid”，别的实例发来的显示它自己的名字。

### 4.2 命名本实例 / 输入框

| 控件 | 说明 |
|---|---|
| 文本框 | 这个实例在共享总线上的名字。**留空**就自动用宿主轨道名（Live 会把轨道名告诉插件）；也可以自己起名，比如“贝斯”“鼓组”。 |
| **命名本实例** | 应用文本框里的名字（回车也等于点它）。名字随工程保存。 |

> 在列表里给“本轨捕获”改名，等价于给这个实例命名。

### 4.3 导入 .mid 素材 / 清空导入 / 清空捕获

| 按钮 | 作用 |
|---|---|
| **导入 .mid 素材** | 打开文件选择框（可多选）把任意 `.mid` 文件当参考素材。多轨文件会拆成多条，进列表的同时也存进当前工程的素材库（重开宿主还在）。 |
| **清空导入** | 删除库里来源是“导入”的全部条目（只影响当前工程）。 |
| **清空捕获** | 清掉当前捕获 + 所有自动保留段 + 库里来源是“捕获”的条目（只影响当前工程）。 |

### 4.4 重命名所选 / 删除所选

| 按钮 | 作用 |
|---|---|
| **重命名所选** | 给列表里选中的那一条改名（和右键“重命名...”一样）。别人的实例发来的素材不能在这里改名，会提示“这条素材不能在这里改名”。 |
| **删除所选** | 只删选中的那一条；属于别的实例的素材不能在这里删。 |

### 4.5 把 .mid 拖进插件窗口

从资源管理器（或 Live 里右键 clip → “导出 MIDI 文件”）把 `.mid` 拖到插件窗口上，窗口会高亮，松手即成为参考素材，效果和“导入 .mid 素材”一样。

> 反过来**不支持**：从插件里往外拖。Ableton Live 会忽略由它自己进程发起的 OLE 拖拽，
> 所以导入一律走“从资源管理器拖文件进 Live”，插件会在生成完成后**自动打开文件夹**替你省掉这一步。

### 4.6 “保留段”：暂停/停止也不会丢

走带一停、或者播放位置往回跳（循环回绕）时，插件会把刚捕获的那一段**自动留档**成一条独立素材，名字形如
`贝斯 保留 21:57:15`，并且立刻写进当前工程的素材库 —— 所以：

* 暂停之后左侧已经捕获的 MIDI **不会消失**，可以直接当参考；
* 关掉宿主再打开（同一个 Live 工程）它们还在；
* 这些保留段同样能**重命名**、能**单独删除**、能勾选/取消参考。

保留段数量有上限（超过后丢最旧的），并由 `清空捕获` 一次性清掉。

### 4.7 底部状态行

一行小字，实时显示：

```
本机已捕获 34 个音符 · 宿主播放中 128.0 BPM      ← 正常，说明插件能读到本轨 MIDI
本机已捕获 0 个音符 · 宿主停止 120.0 BPM         ← 还没收到 MIDI：检查接法（§8）
```

下面还有一段“用法”提示，写的就是放置、接法与导入结果的三句话。

## 5. ② 你的要求（生成区）

### 5.1 常用要求 ▾（模板下拉）

| 模板 | 会自动填好的内容 |
|---|---|
| 鼓组 · Drum & Bass | 风格 `Drum & Bass`、乐器 `鼓组`、小节数 `4` |
| 鼓组 · House/Tech | 风格 `House`、乐器 `鼓组`、小节数 `4` |
| 贝斯线 | 乐器 `贝斯`、小节数 `4` |
| 和弦铺底 / Pad | 乐器 `Pad 弦乐`、小节数 `8` |
| 加花 / 过门 | 乐器 `鼓组`、小节数 `1` |
| 对位旋律 | 乐器 `主音`、小节数 `4` |

选中一条模板后：**风格 / 乐器 / 调性 / 小节数**会被填好，并要求文字**追加**到要求框的末尾
（不是覆盖！你已经写的内容永远保留，模板只是加一段新的）。之后你可以随意改文字，或再点生成。

### 5.2 要求输入框（自然语言）

* 这里写你要什么，中英文都行。比如：“根据贝斯线写一段 4 小节 DnB 鼓组，保持切分感，加一些鬼音军鼓”。
* 内容随工程保存，重开宿主还在。
* 想看最终发给模型的东西：点 **查看提示词**（不花 token）。

### 5.3 风格 / 乐器/音色 / 调性

| 字段 | 作用 | 例子 |
|---|---|---|
| 风格 | 写进提示词的风格标签 | `Drum & Bass`、`Lo-fi`、`City Pop` |
| 乐器/音色 | 让模型选对音域和写法 | `鼓组`、`贝斯`、`Pad 弦乐`、`主音` |
| 调性 | 约束调性/音阶 | `F# minor`、`跟随源轨道` |

### 5.4 小节数 / 创意程度 / 通道 / 移调

| 控件 | 范围 | 说明 |
|---|---|---|
| **小节数** | 1–128（默认 8） | 要求模型生成的长度。**手动随时可改**；勾了“长度=循环长度”后它会被灰掉，自动跟随 Live 的 loop 长度。 |
| **创意程度**（temperature） | 0.00–2.00（默认 0.70） | 越小越贴着参考素材，越大越大胆。想稳妥先 0.3–0.6。 |
| **通道** | 1–16（默认 1） | 生成结果使用的 MIDI 通道。鼓建议第 10 通道。 |
| **移调** | -24 – +24 半音（默认 0） | 对生成结果做整体移调，不动参考素材。 |

### 5.5 播放/捕获开关

| 开关 | 默认 | 作用 |
|---|---|---|
| **共享给其它实例** | 开 | 把本轨捕获发布到共享总线，让同一工程里别的实例看得见（方式 A 的关键）。关掉就只有宿主路由/导入这两种素材来源。 |
| **直接输出 MIDI** | 关 | 让生成的音符实时从插件输出给下游设备。注意 Live 把本插件登记为“音频效果器”，音频效果位于乐器**之后**，所以能不能送达下游乐器取决于宿主；不确定时用文件导入。 |
| **跟随宿主** | 开 | 输出/试听时跟着宿主走带位置走。 |
| **循环** | 开 | 输出/试听时循环播放生成的小片段。 |
| **长度=循环长度** | 关 | 生成长度自动等于宿主 loop 的小节数（此时“小节数”被灰掉）。 |
| **停止后自动生成** | 关 | 打开后：走带从“播放”变成“停止”时自动发请求并写盘（有 10 秒冷却，避免误触发浪费 token）。生成端会自动勾选参考素材里音符数 ≥ 4 的轨道。 |

### 5.6 生成 MIDI / 取消 / 查看提示词

| 按钮 | 作用 |
|---|---|
| **生成 MIDI** | 把勾选的参考素材 + 你要的文字 + 风格/乐器/调性/长度/通道/移调打包成提示词，发给 DeepSeek，后台线程跑；进度、HTTP 状态、耗时、token 用量都会写进下面的日志框。生成结果存到当前工程文件夹，并按设置决定是否自动打开文件夹。 |
| **取消** | 尽力取消正在进行的请求（会在收到下一个数据块时中断）。 |
| **查看提示词** | 在日志框里显示即将发送的完整提示词（含素材编码：`起始拍:音高:时值:力度`），不花钱、不联网。 |

### 5.7 日志框

显示最近的操作与请求记录，例如：

提示词: 4395 字符, 约 1402 tokens

说明: 跟随贝斯律动的切分鼓组

已保存: 文档\DeepSeek MIDI Bridge\我的歌\piano_accompaniment_4bars.mid

## 8. 四种接法：怎么让它“看见”别的音轨

VST3 插件天生只能看到“流经自己”的 MIDI，所以要让插件读到别的音轨，选一种接法：

### 方式 A：跨音轨共享总线（零路由配置，多轨一起参考）

1. 在**源音轨**（如贝斯轨）的设备链里加入一个本插件；
2. 在这个实例里填“命名本实例 = 贝斯”，确认 **共享给其它实例** 是勾上的；
3. 在**目标音轨**（新 MIDI 轨，后面接你要用的乐器）里再加一个本插件；
4. 播放几小节，目标轨的 ① 里就会出现 `贝斯 128 个音符, 4 小节, 128.0 BPM`；
5. 勾选它 → 写要求 → 生成。

* 适合：一次采集多条轨（鼓、贝斯、和声都能被看到），Live 里不需要改任何路由。
* 注意：在 Live 里两个实例都表现为“音频效果器”，位于设备链的音频效果段；Live 会把本轨的 MIDI 一并送到链上的插件，所以源轨实例能看到本轨音符。
* 素材**按工程隔离**：总线上的条目带工程 id，打开另一个 Live 工程不会看到本工程的素材（反之亦然）。

### 方式 B：用 Live 自带 MIDI 路由（最稳）

1. 把插件放在**目标轨**；
2. 展开目标轨的 **MIDI From**：上半部分选**源轨**，下半部分选 `Post FX`（或 `Pre FX`），Monitor 设为 `In`；
3. 播放源轨的 clip，插件立刻收到源轨 MIDI，① 里就会出现它（此方式不需要源轨放第二个实例，也不需要共享总线）。

* 适合：只跟着一条轨写；这是“读取其它音轨”最可靠的通路。

### 方式 B+：直接把 `.mid` 拖进插件窗口

* 任何来源的 `.mid`（Live 里右键 clip → “导出 MIDI 文件”，或磁盘上任意 MIDI）都可以**拖到插件窗口上**，或点 **导入 .mid 素材**；
* 不依赖任何路由或插件分类，适合快速试素材。

### 方式 C：只当“生成器”用

* 不参考任何轨道：直接写要求（或者在 ① 里导入一段素材当参考）；
* 适合：从零写鼓组、写和声、做变奏。

### 把结果变成声音

1. **文件导入（推荐，一定可行）**：生成完成后自动打开文件夹并选中 `.mid` → 从资源管理器拖到 Live 的 Session 格 / Arrangement → 得到 clip → 再拖到任何乐器轨。多轨结果每轨都有一个独立文件。
2. **实时输出（可选）**：勾 **直接输出 MIDI**，让生成的音符实时送到下游设备；勾 **跟随宿主** 跟走带，勾 **循环** 让小片段反复播放；没有走带时用 **试听** 按钮让它自己跑时钟（这条一定能听到，用来验证生成结果）。

## 8.5 在其它宿主里使用（Cubase / Studio One / REAPER / Bitwig / FL Studio…）

插件是标准 VST3，装在 `C:\Program Files\Common Files\VST3` 就会被所有宿主扫到。
差别只在两件事：**宿主怎么把轨道的 MIDI 送进效果器**，以及**宿主是否把插件放到独立进程**。

| 宿主 | 怎么让它读到轨道 MIDI | 备注 |
|---|---|---|
| **Ableton Live** | 方式 A（共享总线）或方式 B（目标轨 `MIDI From` 选源轨） | 实测通过；Live 只扫描系统 VST3 目录 |
| **Cubase / Nuendo** | 轨道插入槽（Insert）里放插件就能收到该轨 MIDI | 想让它在 **MIDI 插槽**里工作，安装时要勾“同时安装纯 MIDI 版本”。VST3 沙箱模式**支持**（多实例会协商成同一个工程） |
| **Studio One** | 乐器轨的插入槽；Note FX 需要纯 MIDI 版本 | 默认 VST3 目录即可 |
| **REAPER** | 任意轨 FX 链（REAPER 会把该轨 MIDI 送进 FX） | “Run in separate process”**支持** |
| **Bitwig Studio** | 设备链里放普通版即可；**Note FX 槽**需要纯 MIDI 版本 | Bitwig 默认“一个实例一个进程”——已支持 |
| **FL Studio** | 混音台 / 通道 FX 槽（可能需要 Verify plugins） | — |
| **Waveform、Mixcraft、Cakewalk、Vienna Ensemble…** | 当普通效果器插在该轨 | — |

**“一个实例一个进程”的宿主**（Bitwig、REAPER 的独立进程模式、Cubase 沙箱）也能正常用：
插件会把“当前工程”写进一个按**宿主进程**命名的会话文件（`%LOCALAPPDATA%\DeepSeekMidiBridge\sessions\`），
所有实例——哪怕各自一个进程——都会读到同一份，于是它们看到同一个工程、共享总线互通。
工程 id 还会随宿主工程一起保存，重开工程同样认得回来。

**纯 MIDI 版本**：安装界面里的复选框
`同时安装纯 MIDI 版本（Cubase / Bitwig 等宿主的 MIDI 插槽用；Ableton Live 无法加载它）`
默认不勾（Live 会拒绝加载没有音频总线的插件）。命令行安装时可以加 `--with-midi`。

**导入生成结果**：任何宿主都可以“从资源管理器把 `.mid` 拖进工程”（生成后插件会自动打开文件夹并选中它）。
“直接输出 MIDI 给下游乐器”能不能用取决于宿主是否允许效果器插件输出 MIDI —— 不确定就用文件导入。

## 9. 工程隔离与文件位置

**一个宿主工程 = 一个文件夹。** 打开哪个工程，就只看到那个工程的素材与生成记录。

```
文档\DeepSeek MIDI Bridge\            ← “输出根目录”（设置里可改）
├── 我的歌\                            ← 工程文件夹（默认取名自宿主工程名：Set / .rpp / .cpr …）
│   ├── piano_accompaniment_4bars.mid  ← 这个工程生成的所有 .mid（多轨会多几个文件）
│   ├── .dmbproject                    ← 工程标记（id + 名字）
│   └── .dmb-library\*.dmbsrc          ← 这个工程捕获到 / 导入的参考素材
├── 另一个工程\
└── 未归类（旧素材）\                   ← 老版本全局库里的素材（一次性搬过来）
```

要点：

* **只显示本工程**：① 里的素材库按工程文件夹读，共享总线条目也带工程 id，别的工程的条目直接忽略；
* **工程 id 随宿主工程保存**：宿主保存工程时插件把 id / 名字 / 文件夹路径写进工程，下次打开同一个工程就认回它；
* **跨实例照旧**：同一 Live 进程里的所有实例协商成同一个工程，所以方式 A 正常工作；
* **名字默认取自 Live 的 Set 名**（VST3 不告诉插件工程路径，插件读宿主窗口标题；读不到时退化成 `宿主名 日期 时间`）；
* **重名自动加序号**：`我的歌`、`我的歌 (2)`、`我的歌 (3)`；
* **什么时候才建文件夹**：只有要往里写东西（生成 `.mid`、归档捕获、导入素材）或 **Live 保存工程**时，文件夹才出现在磁盘上 —— 只是打开插件看一眼不会留下空目录；
* **老素材**：升级前 `%LOCALAPPDATA%\DeepSeekMidiBridge\library\` 里的素材会被搬进 `未归类（旧素材）\`，用设置里的 **并入未归类素材** 并进当前工程，或从“当前工程”下拉框切换过去用它；
* 素材库每个工程最多保留 32 条（超出按时间丢最旧的）。

## 10. 完整工作流示例

### 例 1：跟着贝斯写一段鼓（方式 A）

1. 贝斯轨设备链加一个本插件，命名“贝斯”，**共享给其它实例** 保持勾选；
2. 新建一条 MIDI 轨，挂上鼓机（Drum Rack），设备链上再加一个本插件；
3. 播放贝斯那几小节；
4. 目标轨 ① 里出现 `贝斯 …`，确认它是 ✔；
5. ② 的 **常用要求 ▾** 选“鼓组 · Drum & Bass”（风格/乐器/小节数自动填好，要求框追加一段文字）；
6. 想更贴素材就把 **创意程度** 调到 0.5；想让长度跟着 Live 的 loop 就把 **长度=循环长度** 勾上；
7. 点 **生成 MIDI**，看日志里的 HTTP/token/耗时；
8. 生成完成后资源管理器自动打开并选中 `.mid` → 拖到鼓机轨的 Session 格 → 得到 clip。

### 例 2：给一条旋律配和声（方式 B）

1. 插件放在**目标轨**（新轨，挂 Pad 音源）；
2. 目标轨 **MIDI From** 选源轨（旋律轨），`Post FX`，Monitor `In`；
3. 播放旋律，① 里出现旋律素材；
4. ② 选“和弦铺底 / Pad”模板，再补一句“避开主旋律同音区，音量和一点”；
5. 生成 → 自动打开文件夹 → 拖进目标轨。

### 例 3：没有宿主也能用（dmb-cli）

```powershell
dmb-cli.exe --reference "C:\...\bass.mid" --prompt "写 4 小节 DnB 鼓组" --bars 4 --out "C:\...\out"
```

见 §11。

## 11. 命令行工具 dmb-cli

和插件共用同一套核心（提示词、API 客户端、解析、写盘），适合批量生成、接入别的流程，或者不打开 Live 先调提示词。

```powershell
dmb-cli.exe --reference <素材.mid> [--reference <再来一个.mid>] `
            --prompt "要求文字"  [--prompt-file <要求.txt>] `
            [--bars 8] [--beats-per-bar 4] [--temperature 0.7] `
            [--channel 1] [--transpose 0] [--max-notes 2000] [--reference-bars 16] `
            [--endpoint https://api.deepseek.com/chat/completions] [--model deepseek-chat] `
            [--key sk-...] [--out <输出目录>] `
            [--print-prompt] [--resave <要修复的.mid>]
```

| 参数 | 说明 |
|---|---|
| `--reference <文件>` | 参考素材（可重复多次）。不写就是“自由创作”。 |
| `--prompt <文字>` / `--prompt-file <文件>` | 你的要求。 |
| `--bars` | 生成小节数（默认 8）。 |
| `--beats-per-bar` | 每小节拍数（默认 4）。 |
| `--temperature` | 创意程度（默认 0.7）。 |
| `--channel` / `--transpose` | 结果通道 / 移调。 |
| `--max-notes` / `--reference-bars` | 与插件里的两个上限一致。 |
| `--endpoint` / `--model` / `--key` | 覆盖 API 设置（不写就用 `settings.json` / `DEEPSEEK_API_KEY`）。 |
| `--out <目录>` | 输出目录（默认 `文档\DeepSeek MIDI Bridge`）。 |
| `--print-prompt` | 只打印提示词，不请求、不写文件（省 token）。 |
| `--resave <文件>` | 把已有 `.mid` 重新读写一遍（例如修复早期版本写出的坏文件）。 |

## 12. 怎么写要求（提示词技巧）

* **写清楚四件事**：风格 / 乐器 / 长度 / 律动，例如“4 小节、Lo-fi、电钢琴、慢速摇摆、留出呼吸”。
* **说清“避让”**：比如“避开贝斯的低频”“不要和主旋律同音区”“副歌前留白”。
* **素材越干净越好**：先 solo 源轨播一遍再采集，杂音/别的轨串进来会污染参考。
* **参考上限是成本开关**：`参考上限(小节)` 越小越便宜。先 8–16 小节试，满意了再加大。
* **不要一次要太多**：先做 2–4 小节，满意后再让它写更长或写变奏。
* **不稳就降温度**：`创意程度` 0.3–0.6 更贴素材；想让它“来点惊喜”再往 1.0 以上。
* **模板只追加不覆盖**：你可以先自己写一段，再点模板，两段会一起发出去（自己删掉不要的部分即可）。
* **先看提示词**：点 **查看提示词**，确认素材和文字都在里面，再点生成。

## 13. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| Live 里找不到插件 | 没扫描 / 装错目录 | 设置 → Plug-Ins → 勾 **Use VST3 Plug-In System Folders** → Rescan（按住 Alt 完整重扫）；确认 `.vst3` 在 `C:\Program Files\Common Files\VST3` 或 `%LOCALAPPDATA%\Programs\Common\VST3` |
| Live 提示 `no valid audio input bus` | 装上了纯 MIDI 版 | 删掉 `DeepSeek MIDI Bridge (MIDI).vst3` 目录（安装程序会自动清理） |
| ① 一直是“（没有数据）” | 没有素材来源 | 按 §8 检查：源轨实例勾了“共享给其它实例”吗？方式 B 的 MIDI From 设置了吗？源轨真的在播放吗？ |
| ① 里有别的实例的名字但没有音符 | 那个实例还没播放过 | 播放几小节；或看那个实例窗口左下角的音符计数 |
| 生成报 `HTTP 401` / Key 错误 | Key 填错或余额不足 | 设置里点 **测试连接**；到 platform.deepseek.com 检查；也可以用环境变量 `DEEPSEEK_API_KEY` |
| 生成的音符完全不对 | 素材脏 / 要求太笼统 / 温度太高 | solo 源轨重采；要求写具体（风格、乐器、音域、律动、避让）；降温度；先做 2–4 小节 |
| 生成完了没看到结果 | 自动打开文件夹被关了 | 点 ③ 的结果条或 **打开文件夹**；文件始终在 `文档\DeepSeek MIDI Bridge\<工程名>\` |
| 结果条写着 `(MISSING)` | 文件被移走/删了 | 看 **诊断日志**；重新生成一次 |
| 拖不进 Live | 拖的方式不对 | **从资源管理器**把 `.mid` 拖到 Live 的轨道/Session 格上（不要在插件窗口内部松手） |
| 插件窗口字发糊 | Live 在拉伸窗口 | 设置里把 **界面缩放** 调成和 Live 的 Scale Factor 一致 |
| 顶部状态行显示“（尚未确定工程）” | 还没决定是哪个工程 | 打开设置面板一次，或者生成/捕获一次即会确定 |
| 打开新工程看不到上个工程的素材 | 这是设计目标 | 想用就用“当前工程”下拉框切过去，或 **并入未归类素材** |
| 改工程名时提示搬不动 | 文件夹里有文件被占用 | 关掉可能打开着那些 `.mid` 的程序，再点一次 |

诊断日志文件：`%LOCALAPPDATA%\DeepSeekMidiBridge\diagnostics.log`（分类前缀：`project` / `result` / `ui` / `bus` 等）。
静默安装/卸载的日志：`%TEMP%\DeepSeekMidiBridge-install.log`。

## 14. 常见问题 FAQ

**Q：它会不会把我别的插件删掉？**
A：不会。卸载只删安装清单里记录、并且位于本插件目录/程序目录内的文件，目录只在变空后才删（详见 §2.2）。安装时也只会覆盖自己的文件。

**Q：API Key 存在哪？安全吗？**
A：明文存在 `%LOCALAPPDATA%\DeepSeekMidiBridge\settings.json`，也会随 Live 工程保存一份（跟着 Set）。
想完全不落盘可以用环境变量 `DEEPSEEK_API_KEY`。界面上只显示掩码。

**Q：生成会花多少钱？**
A：取决于 `参考上限(小节)`、素材长度和生成长度。实测：118 小节的贝斯全发 ≈ 15.7k tokens；
只发前 16 小节 ≈ 4.1k tokens；输出 4 小节鼓组一次约 4.1k tokens、3.7 秒。
先点 **查看提示词** 看估算（日志里会写“约 N tokens”）。

**Q：重开宿主我捕获的素材还在吗？**
A：在。归档的捕获段与导入的 `.mid` 都会自动写进**当前工程**的素材库；重开同一个 Live 工程即可继续用。

**Q：换一台电脑要重新设置吗？**
A：API Key / 模型等本机设置不跟着走（每台机器自己的 `settings.json`）；但**每个 Live 工程里保存的插件状态**会带着走，所以打开工程后 Key 会从工程里恢复；没有的话回落到本机设置或环境变量。

**Q：同一个 Live 工程里放很多个实例会不会互相干扰？**
A：不会。所有实例会协商成同一个“当前工程”，共享总线按工程 id 过滤，素材列表按你的勾选决定参考哪些。

**Q：卸载后我生成的 MIDI 还在吗？**
A：在（默认不删）。只有你在卸载界面勾选“同时删除我生成的 MIDI 与工程文件夹”才会删掉。

**Q：可以装在别的盘吗？**
A：可以，用“浏览…”选目录。但 Live 只自动扫描系统 VST3 目录，所以要在 Live 的 Plug-Ins 设置里手动添加该目录。

**Q：支持 macOS 吗？**
A：当前只构建 Windows x64。

## 16. 已知限制

* 插件**无法自动得知宿主音轨的名字**（VST3 不提供该信息），源轨显示名要么由宿主通过通道上下文给出，要么在 ① 里手动命名。
* **工程是靠插件自己认的**（随工程保存的状态 + 宿主窗口标题里的工程名 + 同一宿主会话内所有实例的协商）。因此：
  * 用宿主的“另存为”另存一份工程时，新工程会**沿用**原工程的文件夹（素材一起带走）；想要独立文件夹就用 `改名并移动文件夹` 或 `新建工程`；
  * Standalone 版本有自己的一个工程；
  * 同一宿主会话里先后打开两个工程时以最后加载的为准（插件约 0.5 秒内自动跟随）。
* **界面不显示你本机的真实路径**：插件和安装/卸载程序把路径显示成
  `文档\DeepSeek MIDI Bridge\我的歌`、`%LOCALAPPDATA%\DeepSeekMidiBridge\…`、
  `C:\Users\administrator\…` 这类**通用形式**，诊断日志同样如此，所以截图或分享日志不会泄露账户名和目录结构。
  真实绝对路径只存在于你选择的位置（工程文件夹、`settings.json`、宿主工程里的插件状态）——功能需要，
  但不会打印到界面上。唯一例外是安装界面的“插件安装位置”输入框：它是你要编辑的目标路径，必须显示真实值。
* **不支持从插件窗口往宿主拖**：宿主会忽略由自己进程发起的 OLE 拖拽。导入走“资源管理器拖文件进工程”，生成后插件会**自动打开文件夹**。
* 但**往插件窗口里拖 `.mid`** 是支持的。
* 参数列表里会出现 2048 个 `MIDI CC x|y` 参数：这是 JUCE 的 VST3 封装为 MIDI 学习/自动化提供的标准行为（不是本插件加的），宿主的自动化列表里可以忽略。
* 实时 MIDI 输出能否送达下游乐器取决于宿主对 VST3 MIDI 输出的处理。
* 网络请求在后台线程执行，“取消”是尽力而为。
* 纯 MIDI 版本没有音频总线，**Ableton Live 拒绝加载它**，所以安装时默认不装（要用 Cubase 的 MIDI 插槽或 Bitwig 的 Note FX 时才勾选，见 §8.5）。
* 安装包没有代码签名，首次运行可能出现 SmartScreen 提示。
